<h1 align="center">Beard</h1>

<p align="center"><em>그래서, 한 줄로 뭔데?</em></p>

<p align="center">원뜻과 말투는 지키고, 읽다가 걸리는 문장만 다듬는 국문 윤문 스킬.</p>

---

당신도 안다. 민머리. 뿔테. 턱수염. 검은 터틀넥은 사계절 입는다. 회의실 맨 끝에 앉아 서른 장짜리 제안서를 넘긴다. 아무 말 없다. 빨간펜으로 두 줄 긋는다. 그리고 묻는다. “그래서, 한 줄로 뭔데?”

Beard는 그를 당신의 AI 에이전트 안에 넣는다. 이미 좋은 문장은 그대로 둔다.

## 설치

**Claude Code.** 두 줄을 따로 입력한다.

```
/plugin marketplace add xxentioo/beard
```
```
/plugin install beard@beard
```

**Codex.** 터미널에서 실행하고 새 스레드를 연다.

```bash
codex plugin marketplace add xxentioo/beard
codex plugin add beard@beard
```

**직접 넣기.** 이 저장소의 `skills/` 아래 다섯 폴더를 Codex는 프로젝트의 `.agents/skills/`에, Claude Code는 `.claude/skills/`에 둔다. 하위 스킬이 `beard` 폴더의 참조 파일을 함께 쓰므로 `beard` 폴더는 항상 같이 둔다.

**그 밖의 에이전트.** [rules/beard.md](rules/beard.md)를 프로젝트의 `AGENTS.md`나 규칙 파일에 붙인다. 명령 없이 늘 켜져 있는 압축판이다.

## 다섯 개의 빨간펜

| 스킬 | 플러그인으로 부를 때 | 하는 일 |
|---|---|---|
| beard | `/beard:beard`, `$beard:beard` | 윤문. lite는 단어와 조사만, full은 기본, ultra는 문단까지 다시 짠다. 보존 기준은 셋 다 같다. |
| beard-review | `/beard:beard-review` | 고치지 않는다. 위치, 걸리는 이유, 처방, 안 고치면 생기는 일을 단 코멘트만 남긴다. |
| beard-audit | `/beard:beard-audit` | 긴 문서를 고치지 않고 진단한다. 메시지, 근거, 구조, 문장 순으로 무엇부터 고칠지 순위를 매긴다. |
| beard-strategy | `/beard:beard-strategy` | 원문에서 한 줄 메시지를 뽑고, 경쟁사를 넣어도 성립하는지 보고, 결론이 먼저 오도록 순서를 다시 잡는다. |
| beard-creative | `/beard:beard-creative` | 원안을 다듬고 관찰, 양보, 질문의 세 갈래 카피를 낸 뒤 탈락 테스트를 거쳐 하나를 고른다. |

직접 넣었다면 앞의 `beard:` 없이 `/beard`, `$beard`로 부른다. 원고 끝에 ‘결과만’이라고 쓰면 본문만 받고, ‘이유도’라고 쓰면 주요 전후 비교가 붙는다. strategy와 creative가 원문에 없던 표현을 내면 `Beard 제안`으로 표시하고, 근거가 없는 주장은 지어내지 않고 `[확인 필요]`로 남긴다.

## 그가 긋는 방식

긋기 전에, 처음 맞는 칸에서 멈춘다.

1. 이미 읽히면 그대로 둔다.
2. 지워도 뜻이 남으면 긋는다.
3. 앞뒤가 같은 말이면 합친다.
4. 단어 하나로 풀리면 그것만 바꾼다.
5. 어순으로 풀리면 어순만.
6. 그래도 안 되면 그 문장만 다시 쓴다.

숫자, 날짜, 부정, 조건, 진행 상태, 직접 인용, 사용자가 고정한 문구는 긋지 않는다. ‘아직 끝나지 않았다’를 ‘진행 중’으로 바꾸지 않는다. 읽기가 나아지지 않으면 고치지 않는다. 줄임말로 바꾸거나 같은 뜻의 단어로 갈아 끼우는 것만으로는 고친 것이 아니다. 고친 뒤에는 원문과 다시 대조한다. 사람처럼 보이려고 없던 경험이나 감정, 일부러 낸 오타를 넣지 않는다. AI가 쓴 글인지 판별하지 않고 탐지기 통과도 약속하지 않는다.

| 원문 | Beard |
|---|---|
| 담당자가 일정 변경에 대한 검토를 진행했다. | 담당자가 일정 변경을 검토했다. |
| 지금부터 신청 일정을 살펴보겠습니다. 신청은 월요일에 시작합니다. | 신청은 월요일에 시작합니다. |
| 문제는 속도가 아니라 누락이다. | 그대로. 실제로 A를 부정하는 대조다. |
| 기다렸다. 하루를 더 기다렸다. | 그대로. 반복이 정서를 만든다. |
| 모두에게 같은 기회를 주었다고 말한다. 그러나 신청 조건에 대한 설명은 일부에게만 전달됐다. | 그대로. 이미 읽힌다. ‘주었다→줬다’만 바꾸면 고친 게 아니다. |

## 기록

| 기록 | 무엇을 |
|---|---|
| 12/12 | 고쳐야 할 AI 말투를 고쳤다 |
| 12/12 | 단서가 있어도 둬야 할 표현은 뒀다 |
| 8/8 | 이미 좋은 글은 손대지 않았다 |
| 24/24 | 뜻이 바뀌기 쉬운 문장을 원문 그대로 지켰다 |

숫자는 beard 0.4.0 개발 회귀 88건(gpt-6-sol)에서 해당 사례만 센 것이다. 1.0.0 이후 판단 규칙을 보강했고, 이 88건을 다시 돌리지는 않았다. 우리가 만든 짧은 개발용 원고이고 고친 12건은 스킬에 실린 예시와 같다. 사람 평가나 다른 스킬과의 비교에서 이겼다는 뜻은 아니다. 집계는 [evidence/beard-v040](evidence/beard-v040/)에 있다.

1.0.2는 두 가지를 보강했다. 읽기 이득이 없는 수정(줄임말 바꾸기, 같은 뜻의 단어 교체)은 하지 않고, 미완료·미착수·진행 중·중단·완료를 구별한다. 실행 전에 고정한 표적 7건을 한 번씩 실행해, 7건 모두 원뜻과 상태를 지키며 기대한 동작을 보였다. 이미 읽히는 문장은 그대로 뒀고, 반말 메시지의 ‘내리었어’는 ‘내렸어’로 고쳤고, ‘아직 끝나지 않았다’를 요약에서도 ‘진행 중’으로 바꾸지 않았다. 개발자가 직접 대조한 짧은 표적 시험이라 사람 평가나 일반 성능의 근거로 쓰지 않는다. 원문·출력·판정은 [evidence/beard-v102-targeted](evidence/beard-v102-targeted/)에 있다.

짧은 원고 24건(업무·안내·칼럼·개인 각 6)을 1.0.1과 1.0.2에 넣은 비교도 남겼다. 원문보다 나아진 것이 21건이고, 1.0.1 대비로는 나음 2·같음 10·비슷함 8·나쁨 4다. 나쁨 4건 중 3건은 실행 환경이 검사 스크립트를 막아 생긴 문제였다. 남은 1건은 담담한 개인 글의 ‘그 변화를’을 ‘그걸’로 바꾼 것으로, 다음 버전에서 살핀다. 1.0.2 출력 20건은 다른 모델(Claude)로 만들어 버전 차이만 떼어 볼 수 없다. 개발자가 직접 비교한 것이고 사람 평가가 아니다. [evidence/beard-v102-reader](evidence/beard-v102-reader/)

1.0.3은 그 비교에서 나온 두 가지를 고쳤다. 지시어 뒤 명사가 초점을 맡으면 대명사로 줄이지 않고(‘그 변화를’을 ‘그걸’로 바꾸지 않음), 문어체 글에 구어 축약을 들이지 않는다. 검사 스크립트를 쓸 수 없는 환경에서는 직접 대조로 확인해 진행하고, ‘결과만’ 요청에 메모를 붙이지 않는다. 새로 쓴 표적 8건을 한 번씩 실행해 8건 모두 원뜻을 지켰고 6건이 기대한 동작을 보였다. 칼럼의 상투적 포장을 남긴 1건이 미달, 이미 읽히던 문장을 조금 줄인 1건이 보류다. 개발자가 직접 대조한 짧은 표적 시험이다. [evidence/beard-v103-targeted](evidence/beard-v103-targeted/)

같은 가상 제안서 한 문단을 다섯 스킬에 넣은 실제 출력은 [evidence/site-demo](evidence/site-demo/)에 있다. 한 번씩만 실행한 기록이라 품질의 근거로 쓰지 않는다.
