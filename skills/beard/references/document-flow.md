# 긴 원고의 범위 추적

전체 문맥과 원문 대조를 한 번에 안정적으로 유지할 수 있으면 그대로 편집한다. 어렵다면 scripts/document_flow.py의 plan/assemble을 사용한다. 6000자 기본 budget은 분할 계획의 조절 가능한 작업 예산이며 모델의 지원 한도·합격 기준이 아니다. 문단 하나가 budget보다 크면 임의로 자르지 않고 oversize_blocks로 알린다. 코드를 무조건 분할하거나 모든 원고에 같은 길이 상한을 적용하지 않는다.

plan은 JSON stdin의 original을 받아 원본 해시, 연속 문자 위치, 고유 문단 ID, 문단별 text/kind, 순서대로 묶은 chunks를 stdout으로 제공한다. 원고를 저장하지 않는다. 입력 전달의 안전한 방식은 verification.md와 같다.

body 문단을 편집할 때 목적·장르·보호 대상·용어와 앞뒤 문맥을 함께 확인한다. 실제로 고칠 이유가 없으면 해당 문단은 원문 그대로 둔다. 코드·표·공백 블록은 protected로 보존한다. 분할한 조각마다 새로운 도입·요약·맺음말을 붙이지 않는다. 문맥에서만 확인할 수 있는 뜻을 추측하지 않는다.

assemble 입력은 original, plan, rewrites다. rewrites는 모든 body ID를 키로 가진 객체이며 값은 실제 편집문 또는 유지한 원문이다. 보호 블록의 키는 넣지 않는다. 문단 안의 내부 구조는 지키고 문단 끝 공백은 조립기가 원본에서 복원한다. 원문과 해시·범위가 다르거나, ID가 중복/누락/추가되거나, 빈 본문이 있거나, 보호된 인용·코드·주소를 바꾸면 조립을 거부한다. 코드를 수정문으로 실행하지 않는다.

조립 결과의 검사 신호를 확인하고 전체 글에서 지시 대상·시점·용어·중복·접속 관계를 다시 대조한다. ID가 모두 있다는 사실은 모든 의미가 보존됐다는 증거가 아니다. 처리하지 않은 문단은 유지했다고 정확히 구별하고, 미완료 부분이 있으면 전체 완료로 표시하지 않는다. 재조립·검수 오류 때 문제 구간을 한 번 보정하며 확인이 안 되면 원문 유지/부분 완료를 알린다.

파일로 작업하는 것은 사용자가 저장을 요청한 경우다. 별도 요청 없이 원고·검사 로그·작업 폴더를 만들거나 원본을 덮어쓰지 않는다. 결과만 요청은 완성 본문만 반환하되, 실제로 부분 처리했다면 그 사실을 숨기지 않는다.
