# beard 편집 판단

생성 자료: rules.md와 slop-patterns.json을 수정한 뒤 build_editing_guide.py로 갱신한다. R/SP는 자체 편집 판단이다. 표현의 실제 역할과 예외를 함께 보고, 수정량을 목표 삼지 않는다. 출처·검증 상태는 설명 요청 때 원장을 확인한다.

## 원칙
### R01 — 서술을 줄이기 전에 진행과 상태를 확인한다
- 적용 조건: 진행·완료·상태를 유지하면서 행위를 우회적으로 설명하는 부분을 덜 수 있을 때.
- 대조: 미완료·미착수·진행 중·중단·완료를 구별한다. ‘아직 끝나지 않았다’처럼 착수·진행 여부가 없는 미완료를 ‘진행 중’으로 좁히지 않고, 원문이 밝힌 진행 상태는 유지한다.
- 수정 예: ‘일정 변경에 대한 검토를 진행하고 있습니다.’ → ‘일정 변경을 검토하고 있습니다.’
- 유지 예외·예: ‘연구팀은 지금 시료를 분석하고 있다.’, ‘서랍에 도장이 있다.’처럼 기능이 있는 ‘있다’를 일괄 삭제하지 않는다.

### R02 — 명사화가 숨긴 동작을 드러낸다
- 적용 조건: 지시 대상과 문장의 초점을 잃지 않고 중복된 동작 표현을 줄일 수 있을 때.
- 수정 예: ‘자료를 검토하는 일을 마쳤다.’ → ‘자료 검토를 마쳤다.’
- 유지 예외·예: ‘내가 원하는 것은 시간이다.’는 대조·초점이 중요할 수 있다. ‘파란 것만 골랐다.’는 구체적인 대상을 가리킬 수 있다.

### R03 — 완곡 표현을 정리해도 확실성은 높이지 않는다
- 적용 조건: 같은 기능을 반복하는 표현을 덜어도 능력·가능성·추측 등 원문의 의미 강도가 유지될 때만.
- 수정 예: 능력을 말하는 문맥에서 ‘이 장비는 동시에 세 작업을 처리할 수 있는 능력이 있다.’ → ‘이 장비는 동시에 세 작업을 처리할 수 있다.’
- 유지 예외·예: ‘결과는 달라질 수 있다.’는 ‘결과는 달라진다’나 실제 발생을 말하는 표현으로 바꾸지 않는다.

### R04 — 문장의 정보와 역할을 함께 본다
- 적용 조건: 사실·주장·근거·조건·정서·독자 배려·강조 가운데 독립적인 역할이 없는 반복에 한정한다.
- 수정 예: 단순 일정 공지에서 ‘접수 마감일은 5일이다. 접수는 5일까지 받는다.’ → ‘접수는 5일까지 받는다.’
- 유지 예외·예: 개인 글의 ‘기다렸다. 하루를 더 기다렸다.’는 시간 경과와 정서를 전달하므로 반복만으로 삭제하지 않는다.

### R05 — 끝맺음이 수행하는 일을 확인한다
- 적용 조건: 결론 뒤에서 새 주장·요약 필요·요청·안내·예의 기능 없이 끝났다는 말만 반복할 때.
- 수정 예: 필요한 준비물만 전달하는 짧은 메모에서 ‘준비물은 신분증 한 장이다. 지금까지 준비물을 살펴보았다.’ → ‘준비물은 신분증 한 장이다.’
- 유지 예외·예: ‘참석 여부를 목요일까지 알려 주세요.’는 다음 행동을 요청하므로 끝부분이어도 유지한다.

### R06 — 연결어보다 문장 사이의 관계를 보존한다
- 적용 조건: 연결어 없이도 사건 순서·인과·대조를 같은 뜻으로 이해할 수 있을 때.
- 수정 예: 이어지는 행동을 담담히 서술하는 문맥에서 ‘자료를 보냈다. 그리고 답장을 기다렸다.’ → ‘자료를 보냈다. 답장을 기다렸다.’
- 유지 예외·예: ‘장비는 도착했다. 그러나 설치 기사는 오지 않았다.’처럼 예상과 다른 관계를 전달할 때는 연결어를 유지할 수 있다.

### R07 — 주체와 행동을 가까이 놓는다
- 적용 조건: 주체·행동이 원문에 이미 분명하고, 우회 표현을 줄여도 책임이나 대상이 바뀌지 않을 때.
- 수정 예: ‘담당자가 일정에 대한 안내를 했다.’ → ‘담당자가 일정을 안내했다.’
- 유지 예외·예: ‘자료가 삭제됐다.’의 행위자가 없으면 ‘관리자가 자료를 삭제했다’로 바꾸지 않는다. 원문이 정한 행위자 중심·대상 중심의 초점도 고려한다.

### R08 — 원문의 호흡을 지키고 읽기 문제가 있을 때만 조절한다
- 적용 조건: 원문의 구체적인 읽기 문제를 확인한 때만 연결·분리를 검토한다. 같은 길이·어미가 반복된다는 사실만으로 고치지 않는다. 이해 가능한 칼럼의 압축 표현을 더 쉬운 설명으로 길게 풀거나, 개인 글의 문장 경계·반복·감각을 정서 해설로 덮지 않는다.
- 대조: 리듬을 조절한 뒤 조사·초점·대조·양태·시점이 바뀌지 않았는지 다시 확인한다. 읽기 이득이 불분명하면 원문을 유지한다. 지시어 뒤 명사가 대상·초점을 맡으면 대명사로 줄이지 않고, 문어체 글에 ‘그걸·이걸’ 같은 구어 축약을 새로 들이지 않는다.
- 수정 예: 일상 서술에서 ‘나는 파일을 받았다. 나는 파일을 열었다.’ → ‘나는 파일을 받아 열었다.’
- 유지 예외·예: ‘멈췄다. 다시 멈췄다.’처럼 반복 자체가 의미를 가지거나 서식에 맞춘 보고서 문장은 억지로 바꾸지 않는다.

## 문맥별 말투 점검

### SP01 — 원고 앞에 붙은 상투적인 안내와 도입
문제 문맥: ‘물론입니다’, ‘지금부터 살펴보겠습니다’, ‘빠르게 변화하는 시대’ 같은 말이 원고의 목적에 기여하지 않고 붙거나 반복된다.
- 수정: 원고 밖의 응답 문구는 빼고, 독자가 알아야 할 핵심 정보에서 시작한다. 시대상·문제 제기가 실제 논거라면 남긴다.
- 유지: ‘이번 장에서는 측정 조건을 먼저 설명한다.’가 장의 구조를 알려 주면 유지한다. 대화 응답을 윤문하는 경우 인사도 문맥의 일부다.
예: 지금부터 신청 일정을 살펴보겠습니다. 신청은 월요일에 시작합니다. → 신청은 월요일에 시작합니다.

### SP02 — 내용을 말하지 않는 의미 부여
문제 문맥: ‘시사하는 바가 크다’, ‘중요한 의미를 지닌다’, ‘주목할 만하다’가 내용을 반복하거나 무엇이 중요한지 밝히지 않은 채 이어진다.
- 수정: 본문에 이미 있는 관찰·판단을 직접 쓴다. 중요성의 근거나 해석이 없으면 만들어 넣지 않는다. 독립적인 평가 주장은 지우지 않고, 설명 요청 시 모호함을 알리거나 확인한다.
- 유지: ‘이 결과는 중요하다’가 필자의 핵심 평가라면 임의로 삭제하지 않는다. 학술적 함의를 실제로 설명한 문단도 유지한다.
예: 이 결과는 신청자가 늘었다는 사실을 보여 주며, 신청자의 증가를 시사한다. → 이 결과는 신청자가 늘었음을 보여 준다.

### SP03 — 습관적으로 격을 높이는 대조 구문
문제 문맥: ‘단순한 A를 넘어 B’, ‘A가 아니라 B’가 실제 차이를 밝히지 않고 같은 구조로 반복된다.
- 수정: 실제 추가 기능·차이·대상을 바로 말한다. A의 부정인지 A에 B를 더한다는 뜻인지 구별한다. ‘A가 아니다’라는 주장은 반드시 보존한다.
- 유지: ‘문제는 속도가 아니라 누락이다.’처럼 오해를 바로잡는 실질적 대조는 남긴다. 이를 ‘속도와 누락이 문제다’로 바꾸지 않는다.
예: 이 기능은 단순한 검색을 넘어 정렬도 지원합니다. → 이 기능은 검색과 정렬을 지원합니다.

### SP04 — 설명을 끊는 질문과 즉답
문제 문맥: 독자가 묻지 않은 질문을 반복해 제시하고 바로 자답해 평서문보다 읽기 어려워진다.
- 수정: 설명문에서는 답의 정보를 평서문으로 연결한다. 질문이 독자 탐색을 돕는 형식이면 유지한다.
- 유지: FAQ, 인터뷰, 실제 독자 질문, 교육용 문답에서는 질문을 남긴다.
예: 언제까지 신청해야 할까요? 신청 마감은 금요일입니다. → 신청 마감은 금요일입니다.

### SP05 — 겹친 강조와 과장된 평가
문제 문맥: ‘획기적’, ‘혁신적’, ‘매우’, ‘완벽한’ 등 평가·강조 표현이 근거보다 앞서거나 비슷한 수식이 겹친다.
- 수정: 중복 수식만 덜고, 본문에 있는 행동·특징·수치로 설명할 수 있으면 그 범위에서 표현한다. 평가의 강도가 실제 주장인 경우 유지한다. 근거가 없다고 숫자를 보충하거나 주장 강도를 조용히 낮추지 않는다.
- 수정: 업무·논증 글에서는 평가와 본문의 실제 논거를 대조한다. 강한 평가가 독립 주장이고 근거가 없으면 결과만 요청에는 의미를 보존하며, 이유 요청에는 근거 확인이 필요한 구절을 알린다. 제공된 사실로 완곡하게 바꿔도 된다고 명시한 경우에만 그 범위에서 조정한다.
- 유지: 브랜드의 의도적인 광고 표현, 직접 인용, ‘완전 차단’처럼 성능 범위를 정한 주장은 임의로 완화하지 않는다.
예: 문서를 빠르고 신속하게 검색합니다. → 문서를 빠르게 검색합니다.

### SP06 — 행동을 숨기는 추상 명사 나열
문제 문맥: ‘강화·제고·구현·추진’, ‘~화·~성·~적’ 같은 추상 표현이 이어져 누가 무엇을 하는지 불분명하다.
- 수정: 원문에 있는 주체·행동·대상을 찾아 동사로 풀고 중복된 명사화를 덜어낸다. 원문에 주체나 실행 방법이 없으면 새로 만들지 않는다.
- 수정: 동작이 이미 명료한 추상어나 칼럼의 압축 표현은 설명형 절로 풀지 않는다. 주체·행동의 실제 모호함을 고치는 이득이 있는 부분만 고친다.
- 유지: 정확한 의미를 가진 전문 개념·사업명·공식 명칭은 그대로 둔다.
예: 담당자가 일정 변경에 대한 검토를 진행했다. → 담당자가 일정 변경을 검토했다.

### SP07 — 번역투처럼 늘어진 관계 표현
문제 문맥: ‘~에 있어서’, ‘~를 통해’, ‘~의 관점에서’ 등이 같은 관계를 간단히 말할 수 있는데 반복된다.
- 수정: 문맥에 맞는 조사·동사로 줄이되 수단·경로·원인·관점의 의미를 구별한다. 모든 피동을 능동으로 바꾸지 않는다.
- 유지: ‘터널을 통해 이동했다’의 실제 경로, 특정 관점의 명시, 행위자를 모르는 피동은 기능이 있으므로 유지할 수 있다.
예: 나는 검색 기능을 통해 문서를 찾았다. → 나는 검색 기능으로 문서를 찾았다.

### SP08 — 가능성과 판단을 여러 겹 둘러싼 서술
문제 문맥: ‘~일 수 있을 것으로 생각된다’ 같은 추측·판단 표현이 겹치거나 능력을 두 번 말한다.
- 수정: 중복만 줄이고 가능성·추측의 강도와 판단 주체를 보존한다. 각 층위에 독립적인 뜻이 있으면 유지한다.
- 유지: ‘원인이 배선에 있을 가능성도 배제할 수 없다.’는 불확실성을 보존해야 한다. ‘배선이 원인이다’로 바꾸지 않는다.
예: 이 장비는 파일을 복구할 수 있는 능력을 갖추고 있습니다. → 이 장비는 파일을 복구할 수 있습니다.

### SP09 — 틀에 맞춘 나열과 연결어의 반복
문제 문맥: 실제 순서·대등 관계와 무관하게 ‘첫째·둘째·셋째’, ‘또한·나아가·더불어’가 이어진다.
- 수정: 독자가 비교할 항목은 목록으로 두고, 이어지는 문장은 필요한 관계만 남긴다. 인과·조건·순서가 있는 단계는 보존한다.
- 유지: 설치 절차의 단계, 병렬 비교 항목, 인과를 명시해야 하는 ‘따라서’는 기능에 따라 유지한다.
예: 또한 파일을 저장한다. 또한 백업을 만든다. → 파일을 저장하고 백업을 만든다.

### SP10 — 끝났다는 말과 요약의 재반복
문제 문맥: ‘결론적으로’, ‘지금까지 알아보았습니다’, ‘기억하세요’가 실제 결론·다음 행동 없이 내용을 다시 포장한다.
- 수정: 본문에서 끝낼 수 있으면 끝내고, 결론·요청·다음 행동이 있으면 그것을 직접 쓴다.
- 유지: 긴 보고서의 요약, 안전 고지, 관계를 위한 인사, 문학적인 여운은 목적을 확인하고 유지한다.
- 유지: 구체적 행동·장면으로 끝난 개인 글에 감정 해설이나 교훈을 추가하지 않는다.
예: 준비물은 신분증이다. 지금까지 준비물을 알아보았다. → 준비물은 신분증이다.

### SP11 — 문장 틀과 종결 리듬의 획일적 반복
문제 문맥: 같은 주어·‘~입니다/~할 수 있습니다’·비슷한 길이와 구조가 문맥의 이유 없이 이어져 흐름이 끊긴다.
- 수정: 같은 주체·시점·관계인 문장은 연결할 수 있으나, 리듬을 다양하게 만들기 위한 말투 교체나 장단문 비율 강제는 하지 않는다.
- 수정: 먼저 읽기 문제를 특정한다. 문제가 없으면 접속사·반복·조사·문장 경계를 유지한다. 길이 다양화나 쉬운 설명을 위해 칼럼의 압축된 표현을 풀지 않는다.
- 유지: 보고서의 통일된 형식, 병렬 규격, 의도적 반복, 높임말 일관성은 지킨다.
- 유지: 반복과 문장 경계가 만드는 긴장·여운·목소리를 지킨다. 감각·행동을 원문에 없는 정서 설명으로 대체하지 않는다.
예: 나는 파일을 받았다. 나는 파일을 열었다. → 나는 파일을 받아 열었다.

### SP12 — 읽기보다 눈에 띄기에 치우친 표식
문제 문맥: 과도한 굵게 표시·이모지·따옴표·대시·괄호 속 영어가 강조 대상 없이 겹쳐 읽기를 방해한다.
- 수정: 원래 정보·우선순위를 유지하고 불필요한 표식만 정리한다. 표시가 경고·접근성·용어 정의를 수행하는지 확인한다.
- 유지: 필수 경고, 표의 구조, 직접 인용, 정의한 약어, 계약·코드의 기호는 보존한다. 강조 자체가 저자의 태도인 문맥도 확인한다.
예: 신청은 **금요일**에 **마감**합니다!!! → 신청은 금요일에 마감합니다.
