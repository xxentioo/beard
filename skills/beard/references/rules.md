# 편집 판단 원칙

아래 R 원칙은 자체 편집 가설이며 공식 처방이 아니다. 작가·교정자의 공개 조언을 참고한 부분도 아래 적용 조건으로 옮긴 것은 프로젝트의 해석이며, 효과 검증과 구별한다. 출처는 sources.json, 공식 연결은 framework.json을 참조한다.

### R01 — 서술을 줄이기 전에 진행과 상태를 확인한다

- 보강 근거: S11 (editorial-advice). 원자료의 발언과 자체 적용은 framework.json의 evidence_support에서 구별한다.
- 근거: S04의 문법 기능 설명, S05의 편집 조언, S09의 자체 적용 기준.
- 근거의 범위: S04는 진행과 결과 상태를 설명한다. 군더더기를 줄였을 때의 자연스러움 효과는 별도 가설이다.
- 적용 조건: 진행·완료·상태를 유지하면서 행위를 우회적으로 설명하는 부분을 덜 수 있을 때.
- 수정 예: ‘일정 변경에 대한 검토를 진행하고 있습니다.’ → ‘일정 변경을 검토하고 있습니다.’
- 유지 예외·예: ‘연구팀은 지금 시료를 분석하고 있다.’, ‘서랍에 도장이 있다.’처럼 기능이 있는 ‘있다’를 일괄 삭제하지 않는다.
- 검증 상태: 언어 기능은 공식 설명 확인. 이 편집 규칙의 품질 평가는 미실시.

### R02 — 명사화가 숨긴 동작을 드러낸다

- 보강 근거: S11 (editorial-advice). 원자료의 발언과 자체 적용은 framework.json의 evidence_support에서 구별한다.
- 근거: S06의 편집 조언, S02의 명료성 방향, S09의 자체 적용 기준.
- 자체 해석: ‘것’의 개수보다 대상이 명확한지, 동작을 우회하는지 살핀다. S02가 모든 ‘것’을 금지한다는 뜻은 아니다.
- 적용 조건: 지시 대상과 문장의 초점을 잃지 않고 중복된 동작 표현을 줄일 수 있을 때.
- 수정 예: ‘자료를 검토하는 일을 마쳤다.’ → ‘자료 검토를 마쳤다.’
- 유지 예외·예: ‘내가 원하는 것은 시간이다.’는 대조·초점이 중요할 수 있다. ‘파란 것만 골랐다.’는 구체적인 대상을 가리킬 수 있다.
- 검증 상태: 편집 가설. 장르별 효과와 초점 보존 평가 필요.

### R03 — 완곡 표현을 정리해도 확실성은 높이지 않는다

- 근거: S03의 능력·가능성 설명, S06의 편집 조언, S09의 자체 보존 기준.
- 자체 해석: 표현이 길다는 이유만으로 가능성·추측을 단정으로 바꾸지 않는다. 허용·의무도 별도로 보존해야 한다.
- 적용 조건: 같은 기능을 반복하는 표현을 덜어도 능력·가능성·추측 등 원문의 의미 강도가 유지될 때만.
- 수정 예: 능력을 말하는 문맥에서 ‘이 장비는 동시에 세 작업을 처리할 수 있는 능력이 있다.’ → ‘이 장비는 동시에 세 작업을 처리할 수 있다.’
- 유지 예외·예: ‘결과는 달라질 수 있다.’는 ‘결과는 달라진다’나 실제 발생을 말하는 표현으로 바꾸지 않는다.
- 검증 상태: 능력·가능성 기능은 공식 설명 확인. 각 구체적 변환의 동등성은 개별 평가 필요.

### R04 — 문장의 정보와 역할을 함께 본다

- 보강 근거: S11, S12, S15 (editorial-advice). 원자료의 발언과 자체 적용은 framework.json의 evidence_support에서 구별한다.
- 근거: S07의 편집 조언, S09의 자체 기능 판단. 외부 효과 입증 자료는 현재 없음.
- 적용 조건: 사실·주장·근거·조건·정서·독자 배려·강조 가운데 독립적인 역할이 없는 반복에 한정한다.
- 수정 예: 단순 일정 공지에서 ‘접수 마감일은 5일이다. 접수는 5일까지 받는다.’ → ‘접수는 5일까지 받는다.’
- 유지 예외·예: 개인 글의 ‘기다렸다. 하루를 더 기다렸다.’는 시간 경과와 정서를 전달하므로 반복만으로 삭제하지 않는다.
- 검증 상태: 편집 가설. 삭제 전후의 정보·담화 기능 대조 필요.

### R05 — 끝맺음이 수행하는 일을 확인한다

- 보강 근거: S12 (editorial-advice). 원자료의 발언과 자체 적용은 framework.json의 evidence_support에서 구별한다.
- 근거: S07의 편집 조언, S09의 자체 장르 기준. 문법 규칙이나 보편적인 글쓰기 법칙이 아니다.
- 적용 조건: 결론 뒤에서 새 주장·요약 필요·요청·안내·예의 기능 없이 끝났다는 말만 반복할 때.
- 수정 예: 필요한 준비물만 전달하는 짧은 메모에서 ‘준비물은 신분증 한 장이다. 지금까지 준비물을 살펴보았다.’ → ‘준비물은 신분증 한 장이다.’
- 유지 예외·예: ‘참석 여부를 목요일까지 알려 주세요.’는 다음 행동을 요청하므로 끝부분이어도 유지한다.
- 검증 상태: 편집 가설. 정보 글과 관계를 위한 글을 구분한 독자 평가 필요.

### R06 — 연결어보다 문장 사이의 관계를 보존한다

- 근거: S08의 편집 조언, S02의 논리적 구성 방향, S09의 자체 관계 보존 기준.
- 적용 조건: 연결어 없이도 사건 순서·인과·대조를 같은 뜻으로 이해할 수 있을 때.
- 수정 예: 이어지는 행동을 담담히 서술하는 문맥에서 ‘자료를 보냈다. 그리고 답장을 기다렸다.’ → ‘자료를 보냈다. 답장을 기다렸다.’
- 유지 예외·예: ‘장비는 도착했다. 그러나 설치 기사는 오지 않았다.’처럼 예상과 다른 관계를 전달할 때는 연결어를 유지할 수 있다.
- 검증 상태: 편집 가설. 삭제 후의 관계 해석을 평가해야 한다.

### R07 — 주체와 행동을 가까이 놓는다

- 보강 근거: S11 (editorial-advice). 원자료의 발언과 자체 적용은 framework.json의 evidence_support에서 구별한다.
- 근거: S02의 호응·명료성 점검, S09의 자체 편집 제안. 이미지에서 직접 제시한 항목은 아니다.
- 적용 조건: 주체·행동이 원문에 이미 분명하고, 우회 표현을 줄여도 책임이나 대상이 바뀌지 않을 때.
- 수정 예: ‘담당자가 일정에 대한 안내를 했다.’ → ‘담당자가 일정을 안내했다.’
- 유지 예외·예: ‘자료가 삭제됐다.’의 행위자가 없으면 ‘관리자가 자료를 삭제했다’로 바꾸지 않는다. 원문이 정한 행위자 중심·대상 중심의 초점도 고려한다.
- 검증 상태: 편집 방향은 지침 참고. 능동화가 항상 낫다는 근거로 확대하지 않으며, 제안의 효과 평가 미실시.

### R08 — 원문의 호흡을 지키고 읽기 문제가 있을 때만 조절한다

- 보강 근거: S13, S14, S15 (editorial-advice). 원자료의 발언과 자체 적용은 framework.json의 evidence_support에서 구별한다.
- 근거: S13·S14의 작품별 호흡·리듬 설명과 S15의 감각에 관한 창작 경험, S09의 자체 윤문 해석. 이 자료들은 편집 효과를 실험적으로 입증한 연구가 아니다.
- 적용 조건: 원문의 구체적인 읽기 문제를 확인한 때만 연결·분리를 검토한다. 같은 길이·어미가 반복된다는 사실만으로 고치지 않는다. 이해 가능한 칼럼의 압축 표현을 더 쉬운 설명으로 길게 풀거나, 개인 글의 문장 경계·반복·감각을 정서 해설로 덮지 않는다.
- 대조: 리듬을 조절한 뒤 조사·초점·대조·양태·시점이 바뀌지 않았는지 다시 확인한다. 읽기 이득이 불분명하면 원문을 유지한다.
- 수정 예: 일상 서술에서 ‘나는 파일을 받았다. 나는 파일을 열었다.’ → ‘나는 파일을 받아 열었다.’
- 유지 예외·예: ‘멈췄다. 다시 멈췄다.’처럼 반복 자체가 의미를 가지거나 서식에 맞춘 보고서 문장은 억지로 바꾸지 않는다.
- 검증 상태: 검증할 가설. 일정한 문장 길이·표준편차·종결어미 비율로 품질이나 AI 작성 여부를 단정하지 않는다.


## 장르와 목소리

업무 글은 용어·논거·조건을, 안내문은 높임말·행동·기한을, 칼럼은 평가와 논증을, 개인 글은 정서와 의도적 반복을 보존한다. 미려한 문장으로 통일하려고 문체를 바꾸지 않는다. 아래 기준은 S11–S15를 참고해 도출한 자체 적용이다.

- 명료한 표현을 설명형 절로 풀 때는 해소할 모호함이 실제로 있는지 확인한다. 쉬워 보인다는 이유만으로 칼럼의 압축감을 줄이지 않는다.
- 업무·논증 글의 상투적인 평가가 근거와 연결되는지 살핀다. 독립 주장을 임의 삭제·완화하지 않고 원고 밖 수치나 이유를 만들지 않는다. 이유 요청 때만 필요한 근거 확인 사항을 본문 뒤에 알린다.
- 원문에 있는 장면·행동·감각으로 정서가 드러나면 그 기능을 지킨다. 개인 경험·감각을 새로 만들거나 교훈으로 끝맺지 않는다.
- 한자를 썼다는 이유만으로 쉬운말로 늘여 바꾸거나, 김훈·김애란 등 특정 작가의 문체를 이식하지 않는다.

## 관리

규칙 ID를 재사용하지 않는다. draft → evaluated는 실제 평가 이력과 적용 범위를 기록한 경우에만, held는 실패와 보류 이유가 있을 때만 표시한다. 단일 정적 검사로 효과를 검증했다고 올리지 않는다.
